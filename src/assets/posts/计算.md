# sensor 变量及计算公式

本文整理 Camera Sensor 联调中常用的变量与公式：HBI/VBI 读取、时钟与 blanking、曝光相关的 Tline/linecount，以及尺寸与 35mm 等效焦距换算。结构按「读数 → 时钟 → 曝光 → 光学换算」排列，便于对照 XML / 驱动配置逐项核对。

---

# HBI / VBI

水平/垂直 blanking（HBI/VBI）是核对 sensor 输出时序与 CSID 捕获是否一致的重要观测值。

## 1. 获取 CSIDclockRate

打开相机后测量 CSID 时钟：

```bash
adb shell 'cat /d/clk/cam_cc_csid_clk/clk_measure'
```

> 路径随平台/内核版本可能不同，以当前树中 `clk_measure` 节点为准。

## 2. 打开 csid HBI/VBI 调试打印

```bash
adb shell "echo 0x80 >> /sys/kernel/debug/camera/ife/ife_csid_debug"
adb shell "echo 0x1 >> /sys/kernel/debug/camera/ife/ife_camif_debug"
```

放开限频日志后，可在 CSID 相关代码中看到 HBI/VBI 打印（示意）：

参考：`cam_ife_csid_hw_ver2.c` 中类似输出：

```c
CAM_INFO_RATE_LIMIT(CAM_ISP,
		"CSID[%u] Resource[id:%d name:%s hbi 0x%x vbi 0x%x]",
		csid_hw->hw_intf->hw_idx, res->res_id, res->res_name, hbi, vbi);
CAM_DBG(CAM_ISP,
		"CSID[%u] Resource[id:%d name:%s hbi 0x%x vbi 0x%x]",
		csid_hw->hw_intf->hw_idx, res->res_id, res->res_name, hbi, vbi);
```

日志示例：

```bash
02-20 11:31:41.753 CAM_DBG: CAM-ISP: cam_ife_csid_ver2_print_hbi_vbi: 6359: CSID[2] Resource[id:5 name:IPP hbi 0x63000c6 vbi 0x6744e8]
```

解读时注意：打印值为硬件计数/编码格式，需结合平台文档换算成周期或时间，再与 `lineLengthPixelClock`、`frameLengthLines` 预期对比。

# clock 计算

## 常用配置项

| 配置项 | 含义（工程理解） |
| --- | --- |
| lineLengthPixelClock | 一行对应的像素时钟计数（行长，含有效+HBlank） |
| frameLengthLines | 一帧行数（含有效+VBlank） |
| minHorizontalBlanking | 水平方向最小 blanking 约束 |
| minVerticalBlanking | 垂直方向最小 blanking 约束 |
| outputPixelClock | 输出像素速率（与 MIPI 配置相关） |
| frameRate | 目标帧率 |
| laneCount | MIPI lane 数 |
| settleTimeNs | MIPI settle 时间（ns） |
| is3Phase | 是否 C-PHY（3-phase） |
| VT CLOCK | 像素阵列/读出相关时钟（VTCLK） |

## VTCLK

这个值可以直接问 FAE，或者计算；联调初期建议直接问 FAE 核对量级，再用公式反推是否自洽。

$$
VTPixelClock = frameRate \times lineLengthPixelClock \times frameLengthLines
$$

也常写成：

$$
fps \approx \frac{VTPixelClock}{lineLengthPixelClock \times frameLengthLines}
$$

## outputPixelClock 计算方法

### C-PHY

$$
outputPixelClock = MIPI\_Rate \times \frac{16}{7} \times 3\ /\ bitsPerPixel
$$

约合：

$$
outputPixelClock = MIPI\_Rate \times 2.28 \times 3\ /\ bitsPerPixel
$$

### D-PHY

$$
outputPixelClock = MIPI\_Rate \times laneCount\ /\ bitsPerPixel
$$

（示例中 `laneCount` 常取 4，以实际 mode 为准。）

核对建议：

1. 先固定 `bitsPerPixel`、lane/C-PHY 配置  
2. 用 MIPI rate 算出 `outputPixelClock`  
3. 再与 sensor mode 表、CSID 配置交叉验证  

## minHorizontalBlanking / minVerticalBlanking

这两个量描述 **sensor 在目标模式下允许的最小 blanking**，用于约束行长/帧长下限，避免写出硬件不支持的时序。

工程关系（概念）：

```text
lineLengthPixelClock  >=  active_width  + minHorizontalBlanking
frameLengthLines      >=  active_height + minVerticalBlanking
```

实践要点：

- datasheet / mode 表会给出 min HBlank / min VBlank 或直接给出最小 LLPCLK / FLL
- 提高帧率时优先减 VBlank（减 FLL），但不得低于最小值，且需满足曝光约束（见下文）
- HBlank 过小可能导致 MIPI 行间隔不足、或与 ISP 行缓冲要求冲突
- 配置 XML 时，若平台有 `minHorizontalBlanking` / `minVerticalBlanking` 字段，应与 mode 表一致，而不是只填「算得通的理想值」

快速自检：

| 检查 | 方法 |
| --- | --- |
| FLL 是否过小 | `FLL >= height + minVBlank`，且 `FLL >= linecount + verticalOffset` |
| LLPCLK 是否过小 | `LLPCLK >= width + minHBlank`，并满足 MIPI 带宽 |
| 帧率是否达标 | 用 VTCLK 反算 fps，再对实测帧中断 |

## settleTimeNs

`settleTimeNs` 对应 MIPI D-PHY/C-PHY 从 LP 进入 HS 后接收端等待的 settle 时间，单位 ns。配小了易出花屏/CRC/不出图，配过大则浪费链路余量（通常仍可出图）。

经验流程：

1. 先按 sensor 模组 / FAE 推荐值填写  
2. 对照 SoC CSI 控制器文档的合法范围  
3. 在临界速率下做高温/低温与长线材验证  
4. 出图异常时，与 lane、连续时钟、终端、速率一并排查，不要只拧 settle  

与帧长/曝光的关系（原笔记）：

> 帧长与曝光时长的关系：帧长 >= 曝光时长 + blanking 时长

tuning 根据驱动中配置的 `verticalOffset` 计算出 Blanking time，填入曝光表：

```shell
/*  verticalOffset:  sensor特性，需要 framelength >= linecount + verticalOffset；  */
BlankingTime = lineReadOutTime * verticalOffset
             = 1 / fps / fll * verticalOffset
```

## Tline & ROT & Linecount

$$
VTPixelClock = frameRate \times lineLengthPixelClock \times frameLengthLines
$$

$$
lineReadOutTime(Tline) = \frac{1}{frameRate \times frameLengthLines}
$$

$$
ReadOutTime = Tline \times frame\_height
$$

$$
Linecount = Exptime\ /\ Tline
$$

### 如何理解 linecount

**linecount 是曝光时间的核心换算桥梁**，与曝光时间强绑定，指传感器完成曝光所对应的行数。

意义：**简化曝光时间的量化配置，适配硬件设计逻辑。** Sensor 的曝光时间若直接用时间单位（如毫秒、秒）配置，需复杂的时钟换算电路；而 linecount 以「行数」为单位，适配 Sensor 逐行曝光的硬件特性。单行处理时间（Tline）可通过像素时钟和行长度精准计算，结合：

$$
曝光时间 = linecount \times Tline
$$

即可把抽象曝光需求转化为硬件可识别的整数行数。这种方式通过计数器实现曝光控制，降低电路复杂度，也减少时间单位换算误差。平台侧通常将曝光需求转化为 linecount 写入传感器寄存器。

代码关系示意：

```cpp
VTPixelClock     = static_cast<UINT64>(
    pResData->lineLengthPixelClock * pResData->frameLengthLines * pResData->frameRate);
lineReadoutTime  = (lineLengthPixelClock * NanoSecondsPerSecond) / VTPixelClock;
DOUBLE lineCount = static_cast<DOUBLE>(exposureTimeNS)
                 / GetLineReadoutTime(resolutionIndex, inputSeamlessType);
```

约束回顾：

```text
frameLengthLines >= linecount + verticalOffset
```

## DOL2 切换计算

DOL（Digital Overlap）/ 多曝光交错模式下，长短曝共享读出时间线，切换 mode 或扩展曝光时要同时满足：

1. **每条曝光的 linecount 约束**（各自 `linecount + offset <= FLL` 或产品定义的 DOL 约束）  
2. **帧结构不变性**：切换后 `LLPCLK/FLL/VTCLK` 与 MIPI 带宽仍匹配  
3. **拼接/合成侧**对长短曝时间比、行偏移的假设不被破坏  

概念计算步骤：

```text
1) 确定目标 fps → 由 VTCLK 反推 FLL（或固定 FLL 反推 fps）
2) 按短曝/长曝曝光时间分别算 linecount_s / linecount_l
3) 检查 DOL 行分布与 min VBlank、读出窗口是否冲突
4) 若不满足：优先提高 FLL（降 fps）或降低长曝上限
```

示意关系（具体系数以 sensor datasheet 的 DOL 定义为准）：

$$
T_{exp,long} = linecount_l \times Tline,\quad
T_{exp,short} = linecount_s \times Tline
$$

切换检查表：

| 检查项 | 失败时现象 |
| --- | --- |
| FLL 不足 | 花屏、掉帧、自动减曝异常 |
| 长短曝比例超限 | HDR 合成伪影、亮度跳变 |
| MIPI 带宽不足 | CRC、不出图 |
| settle/lane 未随 mode 更新 | 仅某一 mode 异常 |

> 不同 sensor 的 DOL2 行排布（是否共享 readout、offset 定义）差异大，最终以模组 datasheet 与平台 XML 字段为准；上文给的是联调时的通用核对顺序。

# sensor 尺寸、35mm 等效焦距、FOV、ZOOM 倍数的换算关系

EFL（Effective Focal Length）指的是**有效焦距**，表示镜头光学系统中与焦距相关的等效量。对于厚透镜或是多片透镜组成的系统（例如照相机镜头），焦距通常以有效焦距 EFL 来表示。EFL 用来描述光学系统聚集光线的能力，并且常用来计算放大相关量。镜头的焦距分为像方焦距和物方焦距：像方焦距是像方主面（后主面）到像方焦点的距离，物方焦距是物方主面（前主面）到物方焦点的距离。有效焦距对于确定视场角和光圈等光学特性至关重要。

## 等效焦距计算方法详解

### 等效焦距的概念和计算

- 等效焦距是将不同尺寸传感器的镜头换算到 35mm 全画幅上的焦距值
- 计算公式：**等效焦距 = 实际焦距 × 画幅系数 (crop factor)**
- 目的是统一参照标准，方便比较不同相机的视角

1. **画幅系数 (crop factor) 计算**
   - 画幅系数 = 35mm 全画幅对角线长度 ÷ 实际传感器对角线长度
   - 35mm 全画幅尺寸为 36mm×24mm，对角线长度约 43.3mm
     - √(36²+24²) = 43.2666mm
   - 画幅系数越大，表示传感器尺寸相对全画幅越小

2. **传感器对角线长度**
   - 对角线长度 = √(传感器宽度² + 传感器高度²)
   - 需要先将像素尺寸转换为物理尺寸 (mm)
   - 转换比例根据 pixel size 与有效阵列确定

### FOV 与 ZOOM（补充）

水平/对角线视场角（近似，小畸变镜头）：

$$
FOV = 2 \arctan\left(\frac{sensor\_dim}{2 \times EFL}\right)
$$

其中 `sensor_dim` 取宽度或对角线，取决于要报 HFOV 还是 DFOV。

光变 / 数码变焦倍数（工程常用比较法）：

$$
Zoom \approx \frac{EFL_{tele}}{EFL_{wide}}
\quad\text{或}\quad
Zoom \approx \frac{FOV_{wide}}{FOV_{tele}}
$$

多摄切换时，应用层展示的「X 倍」应对齐：**等效焦距比**或产品定义的视场比，并与 crop 后的有效阵列一致。

### 具体计算示例

1. **示例 1**
   - 传感器参数：
     - 分辨率: 4096×3072 像素
     - 物理尺寸: 约 1/2 英寸 (7.9mm×5.9mm)
     - 实际焦距: 5.6mm
   - 详细计算步骤：
     - 计算传感器对角线: √(7.9mm² + 5.9mm²) = 7.9mm（按原笔记采用的等效口径/对角线取值）
     - 计算画幅系数: 43.3mm ÷ 7.9mm = 5.5
     - 计算等效焦距: 5.6mm × 5.5 = 31mm
   - 备注：若改用像素阵列物理宽高严格求对角线，数值会不同；对比规格书时先确认 image area 定义。

2. **示例 2（OV50Q）**
   - 传感器参数
     - 分辨率 8192×6144
     - pixel size: 1.197 µm × 1.197 µm
     - 物理尺寸: 约 1/1.3" (9805.824µm × 7354.368µm)
       - 手册 image area: 9824.976µm × 7392.672µm，可能含 offset（宽左右约 8 pixel，高约 16 pixel）
     - 实际焦距 (EFL)：6.62mm
   - 详细计算步骤：
     - 对角线：√(9805.824² + 7354.368²) ≈ 12.25728mm
     - cropFactor: 43.2666 / 12.25728 ≈ 3.53
     - 等效焦距: 6.62 × 3.53 ≈ 23.37mm

3. **示例 3（通用模板）**
   - 已知：像素尺寸 `p`（µm）、有效阵列 `W×H`、镜头 EFL（mm）
   - 步骤：
     1. 宽度 mm = `W * p / 1000`，高度 mm = `H * p / 1000`
     2. 对角线 mm = √(宽² + 高²)
     3. crop = 43.2666 / 对角线
     4. 等效焦距 = EFL × crop
     5. （可选）DFOV = 2·arctan(对角线 / (2·EFL))
   - 数值例：`p=1.0µm`，`4000×3000`，`EFL=4.5mm`
     - 尺寸 = 4.0mm × 3.0mm，对角线 = 5.0mm
     - crop = 43.2666 / 5.0 ≈ 8.65
     - 等效焦距 ≈ 38.9mm

### 补充说明

- 等效焦距主要用于：
  - 在不同画幅相机间进行视角比较
  - 评估广角/长焦等镜头特性
  - 选择适合拍摄场景的镜头
- 同样焦距的镜头在小传感器上会显得更「长焦」
- 计算时统一使用**有效成像区**还是 **image area（含 dummy）**，并在笔记中标注来源，避免 crop 来回跳

## 总结

- **HBI/VBI**：用 CSID debug 对照 mode 时序  
- **VTCLK / LLPCLK / FLL**：决定帧率；outputPixelClock 由 MIPI rate 与 lane/C-PHY 反推  
- **min H/V blanking 与 settleTimeNs**：分别是阵列时序与 MIPI 链路的边界条件  
- **linecount**：曝光的一行单位量化；始终检查 `FLL >= linecount + verticalOffset`  
- **等效焦距**：EFL × crop；FOV/Zoom 用几何关系与产品定义对齐  

联调顺序建议：先时钟与 MIPI 出图，再锁帧率与 blanking，最后标定曝光表与光学展示倍数。
