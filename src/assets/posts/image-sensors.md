# 图像传感器的工作原理与应用

图像传感器把光子变成可被 ISP / SoC 处理的数字帧。对 Camera 驱动工程师而言，理解光电转换、读出时序与接口约束，比记住一堆型号参数更重要——后面的寄存器表、HBI/VBI、曝光与帧率都建立在这些原理之上。

## 背景

消费与工业成像几乎都被 CMOS 主导，但 CCD 仍出现在部分科学成像与老产线中。驱动侧常见问题往往不是「像素不够」，而是：

- 帧率与 MIPI 带宽不匹配
- 曝光、帧长、行长约束被破坏导致黑屏/花屏
- 噪声、坏点、黑电平在 ISP 前端未对齐
- 多摄同步、DOL/Stagger HDR 时序难对齐

## 传感器类型

### CMOS 传感器

- **低功耗、高集成度**：像素阵列、ADC、时序控制、部分 ISP 功能可片上集成
- **支持片上系统集成**：便于手机、安防 IPC、车载等大规模量产
- **成本相对可控**：工艺与良率成熟，规格梯度丰富（分辨率、像素尺寸、HDR 能力）

CMOS 常见读出方式为逐行/卷帘快门；全局快门 CMOS 在运动场景与机器视觉中价值更高，但代价是噪声与成本。

### CCD 传感器

- **更高的图像质量潜力**：电荷转移路径统一，历史上在均匀性与部分噪声指标上占优
- **更好的噪声控制空间**：在低温/科学成像中仍有优势
- **更高的电耗与系统复杂度**：需要多路偏置与驱动电压，不利于移动端

| 维度 | CMOS | CCD |
| --- | --- | --- |
| 功耗 | 较低 | 较高 |
| 集成度 | 高（片上 ADC/时序） | 低（外围复杂） |
| 读出速度 | 易做高帧率 | 受转移速率限制 |
| 卷帘/全局 | 卷帘为主，全局可选 | 多为全局类行为 |
| 典型市场 | 手机、安防、车载 | 科学、部分工业遗产系统 |

## 光电转换过程

1. **光子捕获**：微透镜与滤色阵列（Bayer / Quad / RYYB 等）决定光谱响应与串扰。
2. **电荷积累**：曝光时间内光电二极管积累电子；满阱容量决定动态范围上限。
3. **电压转换**：源极跟随 / FD 节点把电荷转为电压；CDS 等技术抑制重置噪声。
4. **数字信号输出**：列 ADC / 片上 ADC 量化后经 MIPI CSI-2（D-PHY/C-PHY）或并行接口输出。

简化链路：

```text
光子 → 电荷(Q) → 电压(V) → ADC → CSI/并行 bitstream → SoC CSID/ISP
```

驱动侧需要同时关心**光学曝光时间**与**电子读出时序**（行长 LLPCLK、帧长 FLL、HBlank/VBlank）。

## 接口与驱动关注点

### 常见控制与数据通路

| 通路 | 作用 |
| --- | --- |
| I2C / I3C / CCI | 寄存器配置：模式、曝光、增益、流控 |
| MIPI CSI-2 | 图像数据与嵌入式元数据 |
| RESET / MCLK / GPIO | 上电时序、时钟、同步与待机 |

上电与开流的典型顺序（概念级）：

```text
电源域按序上电 → 释放 RESET → 提供 MCLK
→ I2C 写 init / mode 表 → 配置链路（lane、settle）
→ stream on → 确认帧中断 / CSID 计数
```

### 与 ISP 的边界

- Sensor：原始 Bayer/YUV、黑电平、曝光增益、HDR 合成前的多曝光帧
- ISP：坏点、LSC、AWB、Tone、降噪、锐化等
- 驱动工程师要保证：**格式、位深、crop、方向、嵌入行**与平台 pipeline 描述一致

调试时可关注：

- 是否有 embedded data / PDAF / histogram 行
- `bitsPerPixel`、lane 数、C-PHY/D-PHY 与 settle time
- 帧率公式是否自洽：`fps ≈ VTCLK / (LLPCLK × FLL)`

## 应用场景

- **智能手机相机**：多摄、OIS/EIS、DOL/Stagger HDR、高帧率视频；功耗与发热是硬约束。
- **安防监控**：长曝光、宽动态、低照；关注星光级噪声与码流稳定性。
- **医疗成像**：一致性、线性度、认证与长期供货；有时仍见专用 CCD/CMOS。
- **工业检测**：全局快门、触发同步、固定镜头与光照；更在意几何与时序可重复性。

## 实践笔记：常见问题

1. **花屏 / 撕裂**：MIPI 速率、lane、连续时钟配置与 SoC 侧不一致。
2. **帧率上不去**：FLL/LLPCLK 被最小 blanking 卡住，或 VTCLK 超限。
3. **曝光异常**：`linecount` 与 `verticalOffset`、最大曝光约束未满足。
4. **颜色偏**：黑电平、OB 区、Bayer 相位（RGGB/BGGR）配错。
5. **多摄不同步**：FSYNC / 软同步策略与主从角色要在模式表里固定。

示例：用 v4l2 粗查节点（具体节点名因平台而异）：

```bash
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video0 --all
# 确认 pixelformat、尺寸、帧率能力是否与 sensor mode 一致
```

## 总结

CMOS 以集成度与成本成为主流，CCD 仍保留在特定高质量场景。理解「光子 → 电荷 → 电压 → 数字流」以及读出时序，才能把寄存器表、MIPI 链路和 ISP 管线串成可调试的系统。对 Camera 驱动而言，接口时序与模式约束往往比像素数量更决定一次联调是否顺利。
