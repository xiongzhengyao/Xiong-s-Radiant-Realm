# 环境传感器在智能家居中的应用

环境传感器是智能家居感知层的基础：温湿度决定舒适与节能策略，空气质量驱动净化与通风，光线信息则把照明从「开关」变成「场景」。本文按选型 → 接口与驱动 → 系统集成 → 调试要点梳理工程笔记，面向 MCU / Linux 嵌入式侧的集成实践。

## 背景与目标

智能家居节点通常受限于：

- 供电：电池或弱电，待机电流要可控
- 总线：I2C / UART / 单总线占多数，地址与上拉需提前规划
- 数据质量：温漂、交叉干扰、响应时间直接影响策略是否可信
- 部署：外壳、开孔位置、热源距离会显著改变读数

目标不是「堆更多传感器」，而是用可维护的驱动与标定流程，把物理量变成稳定、可解释的输入。

## 常见环境传感器

### 温湿度传感器

| 型号 | 接口 | 典型精度 | 备注 |
| --- | --- | --- | --- |
| DHT11 / DHT22 | 单总线 | DHT11 偏低，DHT22 可用 | 成本低，时序挑剔，不适合高可靠节点 |
| SHT20 / SHT30 | I2C | 湿度约 ±2%RH 量级 | 工业/消费级常用，驱动成熟 |
| BME280 | I2C / SPI | 温湿压一体 | 气压可用于楼层/天气辅助，注意散热布局 |

选型时优先看：接口是否与现有总线冲突、是否需要加热/校准命令、封装是否便于开孔取样。

### 空气质量传感器

| 系列 / 型号 | 原理概要 | 适用场景 |
| --- | --- | --- |
| MQ 系列 | 金属氧化物半导体 | 烟雾、酒精、可燃气体等粗粒度告警 |
| CCS811 | eCO2 / TVOC 估算 | 室内通风提醒（需烧机与湿度补偿） |
| SGP30 | TVOC / eCO2 | 长期稳定性相对更好，注意基线维护 |

空气质量类器件读数多是**间接估算**，工程上应把「趋势与阈值」作为策略输入，避免把瞬时 ppm 当绝对真值。

### 光线传感器

| 型号 | 能力 | 典型用途 |
| --- | --- | --- |
| BH1750 | 照度 (lux) | 自动调光、昼夜模式 |
| TSL2561 | 可见光 + IR | 可做简单光谱加权 |
| VEML6070 | UV | 户外/健康相关提示（室内价值有限） |

智能照明更关心「人眼感知亮度」与窗帘/灯具联动；标定环境（玻璃、遮光罩）往往比芯片 datasheet 更影响体验。

## 应用场景

1. **自动温控**：温湿度阈值 + 滞后区间驱动空调/地暖；避免单点抖动导致频繁启停。
2. **空气净化**：TVOC / eCO2 上升触发新风或净化档位；配合门窗状态更稳妥。
3. **智能照明**：lux 低于阈值开灯，高于阈值关灯或降功率；可叠加人体存在检测。
4. **舒适度监测**：温湿压与空气质量合成「舒适指数」，用于面板展示与自动化规则。

## 接口与驱动实践

### 通信协议

- **I2C**：SHT3x、BME280、BH1750 等；注意地址冲突（如 0x44 / 0x76）与上拉电阻。
- **单总线**：DHT 系列；对时序与中断延迟敏感，RTOS 任务里建议关中断短临界区或改用硬件定时。
- **UART / PWM**：部分气体模块输出模拟或串口协议，需 ADC 标定或协议解析状态机。

示例：Linux 用户态用 `i2c-dev` 读 BH1750（连续高分辨率模式）：

```c
#include <linux/i2c-dev.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdint.h>
#include <stdio.h>

int main(void) {
    int fd = open("/dev/i2c-1", O_RDWR);
    if (fd < 0) return 1;
    if (ioctl(fd, I2C_SLAVE, 0x23) < 0) return 1;

    uint8_t cmd = 0x10; /* Continuously H-resolution mode */
    write(fd, &cmd, 1);
    usleep(180000);

    uint8_t buf[2];
    if (read(fd, buf, 2) != 2) return 1;
    uint16_t raw = (buf[0] << 8) | buf[1];
    float lux = raw / 1.2f;
    printf("lux=%.1f\n", lux);
    close(fd);
    return 0;
}
```

### 数据采集与滤波

工程上常用简单而有效的链路：

1. 按 datasheet 等待转换完成（勿在转换中读）
2. 滑动平均或一阶低通抑制噪声
3. 异常值剔除（突变超过物理合理范围则丢弃）
4. 上报周期与本地策略周期解耦（采集快、决策慢）

```text
采样 → 合法性检查 → 低通滤波 → 阈值/迟滞决策 → 执行器 / 云端上报
```

## 系统集成

- **MCU 选型**：节点级用 Cortex-M / RISC-V + FreeRTOS/RT-Thread 足够；需要本地规则与多设备桥接时再上 Linux。
- **通信协议**：传感器侧 I2C/单总线；到网关可用 MQTT / Matter / Zigbee 等，保持「传感数据模型」稳定。
- **供电方案**：注意传感器加热/LED 脉冲电流；地弹与模拟前端共地干扰会导致温湿度跳变。
- **数据采集**：统一时间戳与单位（°C、%RH、lux、ppb）；持久化校准偏移到 NVM。

布局建议：

| 注意点 | 说明 |
| --- | --- |
| 远离热源 | MCU、DC-DC、屏幕背光会抬高本地温度 |
| 开孔与腔体 | 湿度传感器需要气流，但要防凝露与灰尘 |
| 气体传感器 | MQ 类需预热；安装位置避免正对出风口 |
| 光线传感器 | 避免被外壳遮挡；滤光片会改变 lux 标定 |

## 调试要点

1. **读数不合理**：先确认上拉、地址、电源纹波，再用逻辑分析仪看 ACK。
2. **湿度偏高/偏低**：外壳密封、焊剂残留、长时间高湿都会漂移；做两点标定更可靠。
3. **TVOC 跳变**：新家具、酒精擦拭、烹饪油烟都会触发；用移动平均 + 冷却时间。
4. **跨设备一致性**：同型号多节点部署时，记录校准偏移表，而不是在策略里硬编码阈值。

## 总结

环境传感器在智能家居中的价值，取决于**选型是否匹配场景、驱动是否尊重时序与校准、系统是否把噪声当成噪声处理**。温湿度、空气质量、光线三类器件覆盖了绝大多数舒适与节能自动化；把接口、供电与外壳因素纳入设计，比单纯追求 datasheet 精度更接近可落地的产品体验。
